# Gmail 附件批量下载 / 打包 zip

中文 Chrome MV3 插件 MVP。只使用已登录 Gmail 页面里的附件下载链接，在浏览器本地逐个读取、生成不压缩的 STORE ZIP。无运行时依赖、服务端、OAuth、Gmail API 或 API key。

## 加载未打包扩展

1. 打开 Chrome 的 `chrome://extensions`，开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目目录。
3. 打开或刷新 `https://mail.google.com/`。在当前搜索结果页或已展开会话右下角点击「打包附件」。
4. 检查文件名、发件人、日期，勾选附件，点击「确认并导出 ZIP」。列清单不扣次数；确认后开始读取附件才扣一次。
5. 失败附件会记录到 ZIP 的 `_失败清单.txt`。点击「逐个下载」重试失败项，不再计次；跨域链接可能打开新标签，Chrome 可能要求允许多文件下载。

列表页只能识别已经加载、显示且带可用下载 URL 的附件 chip。只有名称而没有链接的 chip 无法下载；请打开会话并展开相应邮件。不会自动翻页、展开全部邮件，也不保证取得搜索结果中的全部附件。

## 设置与免费次数

点击扩展图标查看当前页面状态、解锁状态与今日剩余次数；从「设置」进入选项页。免费版每天本机日期 3 次导出，所有标签页共享，由后台串行写入。失败的导出尝试已开始网络读取，也会占用次数，不退款。

默认文件名：`YYYY-MM-DD_发件人_原文件名`。支持按发件人或日期分文件夹。未知元数据明确标注为「日期未知」「发件人未知」；非法字符替换为下划线，重名添加 ` (2)`，保留扩展名。ZIP 名为 `Gmail附件_YYYYMMDD-HHmm.zip`。

生成本地测试解锁码：

```sh
node scripts/gen-license.mjs
```

把输出的 `GAZ1.…` 填入设置页保存。公开 SHA-256 校验仅用于本地 MVP 演示，不是安全授权系统。清除后恢复当天已记录的免费用量。超限入口：「有问题请联系我」→ 小红书私信「珊哥爱读书」。链接打开小红书首页，需自行搜索该账号。

## 测试

需要 Node.js 20 或更新版本，无需安装依赖：

```sh
npm test
```

覆盖 quota、license、命名、附件链接解析、ZIP 二进制结构、manifest 和后台消息计次。所有工具库同时导出 `globalThis.GmailZip` 与 CommonJS。

## 边界与隐私

邮件和附件不上传到任何第三方。仅允许 Gmail 与 `mail-attachment.googleusercontent.com` 两个 HTTPS 域名；后备链接只来自同一安全解析器。content script 的 fetch 即使拥有 host_permissions 仍受页面 CORS 约束，Google 重定向、登录过期或安全策略可能使读取失败。

ZIP 在内存中构建，会同时持有附件和编码副本；大附件应分批处理。未实现 ZIP64、流式打包或压缩，不适合接近 4 GiB 的包。不要将一次全量导出作为备份方案。Gmail DOM 改版、日期本地化或隐藏内容会影响收集和元数据准确性。

真实 Gmail 登录态及浏览器交互需手动验收，见 [功能地图](docs/FEATURE_MAP.md)。
